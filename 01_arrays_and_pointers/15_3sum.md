## 📌 Problem in Plain English

Given an integer array `nums`, return **all unique triplets** `[nums[i], nums[j], nums[k]]` such that:
$$i \ne j \ne k \quad \text{and} \quad nums[i] + nums[j] + nums[k] == 0$$

> **The Big Constraint:** The solution set **must not contain duplicate triplets**.

```text
Example 1:
Input: nums = [-1, 0, 1, 2, -1, -4]
Sorted: [-4, -1, -1, 0, 1, 2]
Output: [[-1, -1, 2], [-1, 0, 1]]

Example 2:
Input: nums = [0, 1, 1]
Output: [] (No triplet sums to 0)

Example 3:
Input: nums = [0, 0, 0]
Output: [[0, 0, 0]]
```

---

## 💡 The "Aha!" Moment: 3Sum is just 2Sum in Disguise!

A brute force approach checks every combination of 3 numbers using 3 nested loops:
$$\mathcal{O}(n^3) \text{ time } \implies 3000^3 = 2.7 \times 10^{10} \text{ operations (Instant TLE!)}$$

### How to turn $\mathcal{O}(n^3)$ into $\mathcal{O}(n^2)$?
Look at the equation:
$$nums[p1] + nums[p2] + nums[p3] = 0$$

Move $nums[p1]$ to the other side:
$$nums[p2] + nums[p3] = -nums[p1]$$

1. **Sort the array first** ($\mathcal{O}(n \log n)$).
2. **Fix an Anchor (`p1`):** Use a `for` loop to pick your first number.
3. **Run Two Pointers on the rest:** Find two numbers to the right of `p1` that add up to $-nums[p1]$. That is literally **Two Sum II (Sorted)**!

```text
       p1 (Anchor)        p2 (left) ────►             ◄──── p3 (right)
       ▼                  ▼                                 ▼
Nums: [ -4  |  -1  |  -1  |  0  |  1  |  2  |  2 ]
```

---

## 🎛️ How to Steer the Pointers (The Volume Knob Analogy)

In a sorted array, numbers go from **Smallest $\to$ Largest**:
* Moving **`p2` forward (`p2 += 1`)** picks a **bigger** number $\to$ **Turns the sum UP 🔊**
* Moving **`p3` backward (`p3 -= 1`)** picks a **smaller** number $\to$ **Turns the sum DOWN 🔉**

```text
If (nums[p1] + nums[p2] + nums[p3] < 0):   Sum is too cold/small! Turn volume UP  -> p2 += 1
If (nums[p1] + nums[p2] + nums[p3] > 0):   Sum is too hot/big!   Turn volume DOWN -> p3 -= 1
If (nums[p1] + nums[p2] + nums[p3] == 0):  Jackpot! Found a valid triplet!
```

## 🚀 The 4 Speedups: From 2325 ms (Beats 5%) to 450 ms (Beats 90%+)

If you implement the basic logic and use `list(set(out))` to remove duplicates, your code will pass but will run at **2325 ms (Beats 5%)**. Here is why and how the 4 speedups fix it:

---

### ⚡ Speedup 1: Early Exit when Anchor is Positive (`nums[p1] > 0`)
Since the array is sorted, every number to the right of `p1` is $\ge nums[p1]$.
* If the smallest number `nums[p1]` is already greater than 0, then `nums[p2]` and `nums[p3]` are also positive!
* Three positive numbers can **never** add up to 0 ($1 + 2 + 3 = 6 \ne 0$).
* **Action:** Immediately `break` the outer loop!

```python
if nums[p1] > 0:
    break
```

---

### ⚡ Speedup 2: Skip Duplicate Anchors
If `nums = [-1, -1, 0, 1]`:
* When `p1 = 0` (value `-1`), you do a full two-pointer scan and find `[-1, 0, 1]`.
* When `p1 = 1` (value `-1` again!), why repeat the exact same search?
* **Action:** Skip it if it's the same as the previous anchor!

```python
if p1 > 0 and nums[p1] == nums[p1 - 1]:
    continue
```

---

### ⚡ Speedup 3: Clean Squeeze Condition
Instead of `while p2 < len(nums) and p3 > p1 and p2 < p3:`, just write `while p2 < p3:`.
* If `p2 < p3`, boundary checks like `< len(nums)` are mathematically redundant and waste CPU cycles on every loop tick.

---

### ⚡ Speedup 4: Skip Identical Twins (The Clothing Outfit Analogy)

> **👕 The Outfit Analogy:**  
> Imagine picking an outfit: **[Shirt, Pants, Shoes]**.  
> * Shirt (`p1`): Black Shirt.  
> * Pants (`p2`): Blue Jeans.  
> * Shoes (`p3`): White Sneakers.  
> 
> That's **Outfit 1: `[Black Shirt, Blue Jeans, White Sneakers]`**.  
> Right next to the blue jeans on the rack is **another identical pair of Blue Jeans**.  
> Would you try on the identical blue jeans with the same shoes and call it a "new outfit"?  
> **No!** You slide past all the identical blue jeans until you see a different pair of pants!

#### Trace on real numbers:
Suppose `nums = [-2, 0, 0, 2, 2]` with anchor `p1 = -2`:

```text
Round 1: p1=-2, p2=0 (idx 1), p3=2 (idx 4)
Sum = -2 + 0 + 2 = 0 -> MATCH! Record [-2, 0, 2]

If we only did p2 += 1 and p3 -= 1:
Round 2: p1=-2, p2=0 (idx 2), p3=2 (idx 3)
Sum = -2 + 0 + 2 = 0 -> DUPLICATE! Recorded [-2, 0, 2] AGAIN!
```

#### The Fix: Fast-forward past identical twins:
```python
p2 += 1
p3 -= 1

# Skip any other numbers identical to what we just used:
while p2 < p3 and nums[p2] == nums[p2 - 1]:
    p2 += 1
while p2 < p3 and nums[p3] == nums[p3 + 1]:
    p3 -= 1
```

## 💻 Complete Optimized Python 3 Solution

```python
class Solution:
    def threeSum(self, nums: list[int]) -> list[list[int]]:
        out = []
        nums.sort()  # Step 1: Must sort first
        n = len(nums)
        
        for p1 in range(n - 2):
            # Speedup 1: If smallest number > 0, sum can NEVER be 0
            if nums[p1] > 0:
                break
                
            # Speedup 2: Skip duplicate anchors
            if p1 > 0 and nums[p1] == nums[p1 - 1]:
                continue
                
            p2 = p1 + 1
            p3 = n - 1
            
            # Speedup 3: Clean squeeze
            while p2 < p3:
                total = nums[p1] + nums[p2] + nums[p3]
                
                if total == 0:
                    out.append([nums[p1], nums[p2], nums[p3]])
                    p2 += 1
                    p3 -= 1
                    
                    # Speedup 4: Skip duplicate twins in-place
                    while p2 < p3 and nums[p2] == nums[p2 - 1]:
                        p2 += 1
                    while p2 < p3 and nums[p3] == nums[p3 + 1]:
                        p3 -= 1
                        
                elif total > 0:
                    p3 -= 1  # Sum too big -> turn volume down!
                else:
                    p2 += 1  # Sum too small -> turn volume up!
                    
        return out
```

---

## ⏱️ Complexity Analysis

* **Time Complexity:** $\mathcal{O}(n^2)$
  * Sorting takes $\mathcal{O}(n \log n)$.
  * The outer loop runs $n$ times. For each iteration, the two pointers traverse the rest of the array in $\mathcal{O}(n)$.
  * Total Time: $\mathcal{O}(n \log n + n^2) = \mathcal{O}(n^2)$.
* **Space Complexity:** $\mathcal{O}(1)$ (ignoring the output array and sorting stack space). No extra HashMaps or Sets needed.
