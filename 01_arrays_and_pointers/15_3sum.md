# LeetCode 15: 3Sum

> **Difficulty:** Medium | **Pattern:** Two Pointers (Fixed Anchor + Inward Squeeze)
> **Link:** [LeetCode 15](https://leetcode.com/problems/3sum/)

## The problem

Given an integer array `nums`, return all unique triplets `[nums[i], nums[j], nums[k]]` with distinct indices $i, j, k$ such that:

$$\text{nums}[i] + \text{nums}[j] + \text{nums}[k] == 0$$

The output must not contain duplicate triplets.

## Why the naive way fails

Checking all $\binom{n}{3}$ triplets with three nested loops takes $\mathcal{O}(n^3)$ time ($\approx 2.7 \times 10^{10}$ operations for $n = 3000$), and deduplicating via a hash set adds heavy tuple-hashing overhead.

## The core trick

Sort `nums` first in $\mathcal{O}(n \log n)$. Then fix the first number at `p1` and reduce the remaining problem to Two Sum II on the sorted slice `nums[p1 + 1 : n]`:

$$\text{nums}[p2] + \text{nums}[p3] = -\text{nums}[p1]$$

```text
       p1 (Anchor)        p2 (left) ────►             ◄──── p3 (right)
       ▼                  ▼                                 ▼
Nums: [-4  |  -1  |  -1  |  0  |  1  |  2  |  2]
```

Four rules eliminate duplicates and wasted work in-place:
1. **Positive anchor break:** If `nums[p1] > 0`, every number to its right is also positive, so the sum can never be `0`. Break out of the outer loop.
2. **Skip duplicate anchors:** If `p1 > 0 and nums[p1] == nums[p1 - 1]`, `continue` to avoid repeating the exact same search.
3. **Steer the sum:** If `total < 0`, increment `p2 += 1`; if `total > 0`, decrement `p3 -= 1`.
4. **Skip duplicate partners after a match:** After recording a triplet and stepping `p2 += 1` and `p3 -= 1`, advance `p2` while `nums[p2] == nums[p2 - 1]` and retreat `p3` while `nums[p3] == nums[p3 + 1]`.

## Step-by-step trace

Input: `nums = [-1, 0, 1, 2, -1, -4]`, sorted: `[-4, -1, -1, 0, 1, 2]`

| `p1` (val) | `p2` (val) | `p3` (val) | `total` | Action | Output |
|---|---|---|---|---|---|
| 0 (-4) | 1 (-1)...4 (1) | 5 (2) | -3...-1 | All sums $< 0$, `p2` reaches `p3` | `[]` |
| 1 (-1) | 2 (-1) | 5 (2) | 0 | Match: record `[-1, -1, 2]`, `p2=3, p3=4` | `[[-1, -1, 2]]` |
| 1 (-1) | 3 (0) | 4 (1) | 0 | Match: record `[-1, 0, 1]`, `p2=4, p3=3` | `[[-1, -1, 2], [-1, 0, 1]]` |
| 2 (-1) | - | - | - | `nums[2] == nums[1]`: skip duplicate anchor | `[[-1, -1, 2], [-1, 0, 1]]` |
| 3 (0) | 4 (1) | 5 (2) | 3 | Sum $> 0$, `p3=4` (loop ends) | `[[-1, -1, 2], [-1, 0, 1]]` |

```python
class Solution:
    def threeSum(self, nums: list[int]) -> list[list[int]]:
        out = []
        nums.sort()
        n = len(nums)

        for p1 in range(n - 2):
            if nums[p1] > 0:
                break
            if p1 > 0 and nums[p1] == nums[p1 - 1]:
                continue

            p2, p3 = p1 + 1, n - 1
            while p2 < p3:
                total = nums[p1] + nums[p2] + nums[p3]
                if total == 0:
                    out.append([nums[p1], nums[p2], nums[p3]])
                    p2 += 1
                    p3 -= 1
                    while p2 < p3 and nums[p2] == nums[p2 - 1]:
                        p2 += 1
                    while p2 < p3 and nums[p3] == nums[p3 + 1]:
                        p3 -= 1
                elif total > 0:
                    p3 -= 1
                else:
                    p2 += 1

        return out
```

## Traps to watch for

* **Checking `nums[p1] == nums[p1 + 1]` instead of `nums[p1 - 1]`:** Skipping when `nums[p1] == nums[p1 + 1]` misses valid triplets like `[-1, -1, 2]` where `p1` and `p2` share the same value. Always compare `p1` against `p1 - 1` (the anchor you already finished processing).
* **Only skipping duplicates on one side:** After a match on `[-2, 0, 0, 2, 2]`, advancing both `p2` and `p3` past their duplicates keeps the code symmetric and avoids redundant comparisons.

## Complexity

* **Time:** $\mathcal{O}(n^2)$ from $\mathcal{O}(n \log n)$ sorting plus $n$ iterations of an $\mathcal{O}(n)$ two-pointer scan.
* **Space:** $\mathcal{O}(1)$ auxiliary space (excluding output and sorting overhead).
