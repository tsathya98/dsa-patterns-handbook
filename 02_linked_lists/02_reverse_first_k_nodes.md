# Reverse first k nodes of a linked list> **Category:** Linked Lists / Pointer Manipulation  > **Source Code:** [`02_reverse_first_k_nodes.py`](./02_reverse_first_k_nodes.py)  > **Prerequisites:** [Reverse Linked List](./206_reverse_linked_list.md)## The problemGiven the head of a linked list and an integer $k$ ($k > 0$, $k \le n$), reverse the first $k$ nodes in-place and reconnect them with the rest of the list.```textInput:  [1] ──► [2] ──► [3] ──► [4] ──► [5] ──► [6] ──► Null   (k = 4)Output: [4] ──► [3] ──► [2] ──► [1] ──► [5] ──► [6] ──► Null```---## Why using a Python list is rejectedConverting the nodes to a Python `list`, reversing the list, and re-linking them takes **$\mathcal{O}(k)$ auxiliary memory**. In technical interviews, linked list reversal problems strictly require an **in-place $\mathcal{O}(1)$ extra memory** solution.---## The core trick1. **The original head becomes the tail:** Node 1 starts at the front of the list, but after reversing the first 4 nodes, Node 1 is the **tail** of that reversed group (`4 -> 3 -> 2 -> 1`).2. **The $k$-th node becomes the new head:** Node 4 was at position $k$, but after reversal, Node 4 is at the **very front** of the entire list.3. **Pointers at the end of $k$ iterations:**   * `prev` is pointing directly at **Node 4** (the new head!).   * `cur` is pointing at **Node 5** (the start of the rest of the list).   * `head` is still holding **Node 1** (the end of the reversed chunk).4. **The Bridge line:** `head.next = cur` glues Node 1 to Node 5!```textBefore the bridge:Reversed piece:    [4] ──► [3] ──► [2] ──► [1] ──► null                   ▲                       ▲                 prev                     head              (New Head!)             (Old Head)Remaining piece:   [5] ──► [6] ──► null                   ▲                  curAfter the bridge (head.next = cur):                   [4] ──► [3] ──► [2] ──► [1] ──► [5] ──► [6] ──► null                   ▲                 prev (Return this!)```### Algorithm steps:* **1. Base checks:** If `head` is null or `k <= 1`, return `head` immediately.* **2. Initialize pointers:** `prev = None`, `cur = head`.* **3. Reverse $k$ nodes:** Run the standard 4-step pointer reversal loop $k$ times:  * `nxt = cur.next` (bookmark next node).  * `cur.next = prev` (flip current node backward).  * `prev = cur` (slide `prev` forward).  * `cur = nxt` (slide `cur` forward).* **4. Bridge to remainder:** Connect the original head to the rest: `head.next = cur`.* **5. Return new head:** Return `prev` (which sits on the $k$-th node, now the front).```playthrough{  "algorithm": "reverse_first_k",  "initial": [1, 2, 3, 4, 5, 6],  "k": 4}```---## Step-by-step trace ($k = 4$)Input: `1 -> 2 -> 3 -> 4 -> 5 -> 6 -> Null`| Step | `prev` node | `cur` node | Reversed chain so far | Remaining chain || :---: | :---: | :---: | :--- | :--- || **Start** | `null` | Node 1 | None | `1 -> 2 -> 3 -> 4 -> 5 -> 6` || **After loop 1** | Node 1 | Node 2 | `1 -> null` | `2 -> 3 -> 4 -> 5 -> 6` || **After loop 2** | Node 2 | Node 3 | `2 -> 1 -> null` | `3 -> 4 -> 5 -> 6` || **After loop 3** | Node 3 | Node 4 | `3 -> 2 -> 1 -> null` | `4 -> 5 -> 6` || **After loop 4** | **Node 4** | **Node 5** | `4 -> 3 -> 2 -> 1 -> null` | `5 -> 6` || **Bridge** | Node 4 | Node 5 | `head.next = cur` $\implies$ `1 -> 5` | `4 -> 3 -> 2 -> 1 -> 5 -> 6` |---## Python 3 implementation<details><summary>Spoiler: Solution Code</summary>```pythonclass Solution:    def reverseFirstK(self, head: Optional[ListNode], k: int) -> Optional[ListNode]:        if not head or k <= 1:            return head        prev = None        cur = head        # 1. Reverse first k nodes        for _ in range(k):            nxt = cur.next            cur.next = prev            prev = cur            cur = nxt        # 2. Reconnect original head (now tail) to the remaining list        head.next = cur        # 3. Return prev (which points to node k, the new start of the list)        return prev```</details>---## Traps to watch for* **Trap 1: Returning `head` instead of `prev`:** Remember that `head` is still holding Node 1! Node 1 is now in the 4th position. Node 4 is at the front, and `prev` points to Node 4.* **Trap 2: Forgetting `head.next = cur`:** If you omit this line, Node 1 remains pointing to `None`, and all nodes after $k$ (nodes 5 and 6) are lost forever.## Complexity* **Time Complexity:** $\mathcal{O}(k)$ single pass over the first $k$ nodes.* **Space Complexity:** $\mathcal{O}(1)$ strictly in-place with zero memory allocation.
